## 4. Experiments and Comparisons

Run the **same set of queries** in all three modes. Fill in the table with short notes.

You can reuse or adapt the queries from `dataset.py`.

| Query | Naive LLM: helpful or harmful? | Retrieval only: helpful or harmful? | RAG: helpful or harmful? | Notes |
|------|---------------------------------|--------------------------------------|---------------------------|-------|
| Where is the auth token generated? | Not tested directly, but no grounding in docs so any answer is a guess | Helpful — correctly ranked AUTH.md first, snippet shows `generate_access_token` in `auth_utils.py` | Helpful — concise, correct answer: "generated by `generate_access_token` function in `auth_utils.py`", cited AUTH.md | RAG gave the cleanest single-sentence answer; retrieval only required the user to read the snippet themselves |
| Which endpoint returns all users? | Not tested directly | Helpful but noisy — top match was DATABASE.md (contains `get_all_users()` helper) ranked above API_REFERENCE.md which has the actual `GET /api/users` endpoint | Not tested directly, but would likely still cite the right endpoint since Gemini can read past the ranking order | Shows a real retrieval limitation: term overlap scoring favored the doc mentioning "users" most often, not the doc with the actual answer |
| what is the color of the sky | N/A (off-topic) | Correctly refused: "I do not know based on these docs." after stopword fix | Correctly refused: "I do not know based on these docs." | Both modes degrade gracefully once the stopword-filtered scoring guardrail was added; before that fix this query returned confident-looking snippets from AUTH/SETUP/DATABASE because "the", "is", "of" matched everywhere |
| how many dogs are there in the world | Not tested directly | Would be refused (no doc contains "dogs") | Correctly refused: "I do not know based on the docs I have." | Clean refusal — no keyword overlap at all, so even the un-tuned threshold works here |

**What patterns did you notice?**

- **Naive LLM looks impressive but untrustworthy** whenever the question sounds answerable from general knowledge (e.g. "how many dogs are there in the world") — it can produce a fluent, confident-sounding answer with zero connection to the actual docs, and there's no way to check its sources.
- **Retrieval only is clearly better** for "where is X defined" style questions once ranking works, because it shows the raw source text — the user can verify the answer themselves instead of trusting a generated sentence. It's also the easiest mode to make *refuse safely*, since refusal is just a score threshold, not a generation decision.
- **Retrieval only is clearly worse** when the correct answer lives in a document that doesn't win the ranking (the "all users" query above) — the user has to manually dig through snippets since there's no synthesis step.
- **RAG is clearly better than both** when the right snippet is retrieved: it synthesizes a direct, short answer and still cites the file, combining retrieval's grounding with the LLM's ability to phrase a precise answer. RAG inherits retrieval's refusal behavior too ("I do not know based on these docs"), so the guardrail protects both modes at once.
